# PDF / JPG — แยกภาพตามกรอบสีน้ำเงิน

เว็บภาษาไทยสำหรับแยกช่องใน PDF และรูปภาพเป็น JPG ด้วย React, Vite, TypeScript และ MUI ประมวลผลบนเบราว์เซอร์ทั้งหมด เอกสารไม่ถูกส่งไปเซิร์ฟเวอร์

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป หรือ Node.js 24 และ npm

```bash
npm install
npm run dev
```

เปิด URL ที่ Vite แสดง เลือกหรือลาก PDF หรือรูปภาพ (JPG, PNG, WebP, BMP) มาวาง ระบบตรวจกรอบสีน้ำเงินทุกหน้าและแยกเป็น JPG ทันที โดยผู้ใช้ไม่ต้องระบุค่าใด ๆ และไม่ต้องกดปุ่มแยกภาพ เมื่อเสร็จแล้วดาวน์โหลดรายภาพหรือรวมเป็น ZIP ได้

`Sample.pdf` มี 2 หน้า หน้าละ 2 คอลัมน์ × 4 แถว รวม 16 ภาพ ระบบใช้กรอบที่ตรวจพบจริงในแต่ละหน้า ไม่อิงชื่อไฟล์หรือพิกัดตัวอย่าง ไฟล์ตัวอย่างไม่ได้รวมใน production build

คัดลอกรูปภาพหรือภาพหน้าจอ แล้วกด **Ctrl+V** (Windows/Linux) หรือ **⌘V** (Mac) บนหน้าเว็บได้ ระบบจะแยกภาพทันที รองรับครั้งละหนึ่งรูป รูปที่วางต้องมีกรอบสีน้ำเงินเช่นเดียวกับการเลือกไฟล์

## ผลลัพธ์

- เก็บเส้นกรอบสีน้ำเงินครบทั้งสี่ด้านของแต่ละภาพ โดยรวมเส้นที่ใช้ร่วมกันไว้ในทั้งสองภาพ ไม่วาดกรอบใหม่ทับเนื้อหา

- รูปภาพใช้ความละเอียดต้นฉบับในการตัด และส่งออก JPG คุณภาพ 90% พื้นหลังขาว เช่นเดียวกับ PDF ต้องมีกรอบสีน้ำเงินแบ่งช่อง

- ตรวจแนวตัดแยกแต่ละหน้า รองรับจำนวนแถว คอลัมน์ และขอบที่ต่างกันระหว่างหน้า
- หากหน้าใดตรวจไม่พบกรอบสีน้ำเงินที่แบ่งช่อง จะแจ้งเลขหน้าและไม่เปิดให้แปลง เพื่อป้องกันการตัดผิดพื้นที่
- PDF ส่งออก JPEG ที่ 200 DPI คุณภาพ 90% พื้นหลังขาว; ค่า DPI ใน metadata อาจขึ้นกับเบราว์เซอร์
- เรียงตามหน้า จากซ้ายไปขวาแล้วบนลงล่าง ชื่อเช่น `Sample_page-01_cell-01.jpg`; ZIP ชื่อ `Sample_images.zip`
- เปลี่ยนไฟล์จะล้างผลลัพธ์เดิมและตรวจกรอบใหม่
- PDF.js worker และฟอนต์ Noto Sans Thai รวมอยู่ในเว็บ ไม่โหลดจาก CDN

`Sample2.png` เป็นตัวอย่างตาราง 2 คอลัมน์ × 4 แถวที่ขนาดช่องไม่เท่ากัน ระบบตัดตามเส้นจริงได้ครบ 8 ภาพ

## ตรวจสอบและ build

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

Unit tests ตรวจการแยกกรอบสีน้ำเงินออกจากเส้นดำ พื้นที่ตัด ลำดับภาพ และการตรวจกรอบพร้อมส่งออก JPG จริงทั้ง 16 ภาพจาก Sample.pdf ส่วน browser tests ตรวจขั้นตอนเลือกไฟล์ แยกภาพทันที ดาวน์โหลด JPG/ZIP เปลี่ยนไฟล์ ไฟล์เสีย และหน้าจอมือถือ

สำหรับ Linux ที่ Chromium ขาด shared libraries ให้ติดตั้งด้วย `npx playwright install-deps chromium` ก่อนรัน browser tests

Production build อยู่ใน `dist/` สำหรับให้บริการผ่าน static hosting โปรเจกต์นี้ยังไม่ได้ deploy

## ข้อจำกัด

รองรับกรอบสีน้ำเงินเป็นตารางขนาดใหญ่ ใช้ตำแหน่งเส้นจริง รองรับแถวและคอลัมน์ขนาดไม่เท่ากัน สูงสุด 20 แถว × 20 คอลัมน์ เส้นแนวนอนต้องครอบคลุมอย่างน้อย 60% ของความกว้างหน้า และเส้นแนวตั้งอย่างน้อย 50% ของความสูงหน้า ยังไม่รองรับกรอบอิสระ ช่องที่รวมเซลล์ หรือกรอบเอียง

ไฟล์ที่มีรหัสผ่านต้องปลดรหัสก่อน การแปลงทีละหน้าช่วยลดหน่วยความจำ แต่ผลลัพธ์และ ZIP ทั้งหมดยังอยู่ในหน่วยความจำ หน้าที่เรนเดอร์เกิน 40 ล้านพิกเซลหรือด้านใดเกิน 16,384 พิกเซลจะแสดงข้อผิดพลาด

รูปภาพรองรับ JPG/JPEG, PNG, WebP และ BMP ที่เบราว์เซอร์อ่านได้ ไม่เกิน 40 ล้านพิกเซล และด้านละ 16,384 พิกเซล ไฟล์เสียหรือไม่มีกรอบสีน้ำเงินจะแสดงข้อผิดพลาด

## Deploy ไป Azure Static Web Apps

Workflow อยู่ที่ `.github/workflows/azure-static-web-apps-black-pond-07d383300.yml` ใช้ Node.js 24 ติดตั้งด้วย `npm ci --include=dev` และ build ด้วย `npm run build` จากนั้นส่งโฟลเดอร์ `dist` ไป Azure โดยตั้ง `skip_app_build: true` เพื่อไม่ให้ Azure build ซ้ำ

เมื่อ push เข้า `main` จะ deploy production ส่วน pull request จะใช้ preview deployment และปิด preview เมื่อปิด PR ใช้ GitHub Actions secret เดิมชื่อ `AZURE_STATIC_WEB_APPS_API_TOKEN_BLACK_POND_07D383300` ซึ่งต้องมี deployment token ของ Azure Static Web App นี้
